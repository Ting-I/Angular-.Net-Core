# Design: 課程簡介 PDF — Save Course Detail as PDF

Generated by /office-hours on 2026-09-09
Branch: worktree-feature-course-pdf
Repo: Ting-I/Angular-.Net-Core
Status: APPROVED
Mode: Startup (intrapreneurship)

## Problem Statement

Sales staff send buyers a link to the public course page (`https://www.uuu.com.tw/Course/Show/{pkid}/{courseId}`). Some buyers cannot use a link: their process needs an attachment that sits next to a purchase order and is read months later by someone who never opens the CMS. The Course detail page (`src/CMS.NG/src/app/features/courses/course-detail/`) needs a 儲存為 PDF button that produces a customer-ready 課程簡介 sheet.

## Demand Evidence

- "A named operator asked" for it. The operator's name and role were not supplied after two requests; this is the largest open gap and is the assignment.
- Recipient: an external customer or corporate buyer, via sales.
- The wall the current workaround hits: "the buyer needs an attachment (email / procurement / PO)".
- Not observed: nobody has used a prototype yet, so no observation evidence exists.

## Status Quo

Operators send the public URL. It costs nothing and never goes stale, so the PDF competes with a working solution. It only wins where a link cannot go: email attachments, procurement portals, PO bundles.

## Target User & Narrowest Wedge

- User: a sales / account operator already on the Course detail page. Name and role: TBD.
- Wedge: one button on the page they are on, producing a one-page (target, not enforced) A4 sheet of buyer-facing fields with a QR code back to the live page. No preview page, no bulk export, no server involvement.

## Constraints

- Angular 20 standalone + PrimeNG 20 frontend; .NET 9 + Dapper API; desktop-only UI by design (no print or viewport-width `@media` rules today; the only media rule is a `prefers-reduced-motion` block in `course-list.scss`).
- Reuse ladder: repo helper → stdlib → native platform → installed dependency. No new dependency for what the browser already does.
- Every endpoint needs a token; RowAudit is for Insert/Update/Delete only.
- `angular.json` component style budget: warn 4 kB, error 8 kB per component stylesheet.
- Body font stack already leads with `'Noto Sans TC'` but no webfont is loaded; print uses the operator's system CJK font (Microsoft JhengHei on the operators' Windows machines).

## Premises

1. **Buyer-facing fields only.** Every `Course` column is on exactly one of these lists. Included: 課程名稱, 官方課程名稱, 課程代碼 (`CourseId`), 原廠課程代碼 (`ProdCourseId`), 原廠, 時數, 點數, 可重聽 (`CanRepeat`), 對應認證 (resolved names only), 教材, 課程目標, 適合對象, 先備知識, 課程大綱, 考試／認證說明, QR code, public URL. Excluded by construction: **`ListPrice` / 牌價 — no price appears on the sheet in any form (gate decision C4, 2026-09-09)**, 主代碼 (pkid, which appears only as a path segment inside the public URL in the footer and nowhere else), 顯示順序, 上架狀態, 課程群組, 上架日期／下架日期 (these are the CMS publish window, not class dates; a buyer would misread them), 友善網址, 對應職務類別, 備註, 其他資訊, 使用狀況 counts, RowAudit. Operator confirms the list; 教材 and 點數's unit are the two most likely to move.
2. **Real vector Traditional Chinese text.** Selectable and searchable in the PDF. A rasterised page fails acceptance.
3. **The browser's print engine makes the PDF.** `window.print()` plus `@media print`. One "Save as PDF" dialog is an accepted cost. No PDF library in Angular, no Chromium or fonts on the API host.
4. **Informational, and carries no price at all.** (Rewritten at the /autoplan Final Gate, decision C4 — supersedes both the office-hours version and the eng review's 4B.) The sheet prints **no `ListPrice`, no 牌價 cell, and no price disclaimer**: a price that disclaims itself invites the phone call the attachment exists to avoid, and a `DEFAULT 0` column cannot tell "free" from "not filled". What C4 actually buys is narrower than "every price conversation goes through the 報價單", and the narrower claim is the defensible one: the sheet's own QR points at a public page that prices the course, so this does not route the buyer through sales — it keeps a **frozen, dated** price off a document that is filed beside a purchase order and read months later, where 統編, tax treatment and validity belong to the 報價單 anyway. The sheet carries 產生日期, the contact block, and the QR to the live page; nothing is frozen or stored.
5. **Read-only on course data, with one write-free ping.** (Amended at the Final Gate, decision C3 — supersedes "frontend-only".) The sheet still needs no new read endpoint: `GET /api/courses/{pkid}` returns everything. But `POST /api/courses/{pkid}/sheet` is added: it changes no row, writes no RowAudit entry, and only emits a structured log line (`operator {userId}/{userName}, course {pkid}/{courseId}, at {local}`) so that **"is this button used at all"** has an answer. ~~"Which sheet did we send in March"~~ is struck: the line records a *print request* — the browser's dialog owns the Save/Cancel choice and no page can observe it — and nothing in this application retains logs today (levels only, no file or EventLog sink, IIS stdout off), so the record is a usage signal, not an archive. The sink and its retention are a `TODOS.md` entry; the time is local, to match RowAudit's own timestamps. It carries the global auth policy like every other endpoint, returns `204`, and is fire-and-forget from the client: its failure never blocks a print.

## Landscape

- jsPDF is the default Angular recommendation, but its `.html()` path cannot render Chinese even with `setFont` (jsPDF issues #2465, #2446); html2canvas rasterises text.
- Server side: QuestPDF has no HTML input by design; Playwright / PuppeteerSharp render faithfully but require a Chromium binary and font provisioning on IIS.
- Eureka: the operator's browser already ships the best CJK PDF renderer on the machine. The feature is a print-first component and a print stylesheet, not a PDF pipeline.

## Cross-Model Perspective

Second opinion from a fresh Claude subagent (Codex not installed), cold-reading a structured summary:

- **Steelman:** a print-only `CourseSheet` component, browser as PDF engine, system CJK font as vector text, nothing stored or audited. The CMS button is the wedge; the component is reusable by a list page or public route later.
- **Key insight:** "the buyer needs an attachment (email / procurement / PO)" means the artifact is *filed* and read out of context months later. Document identity (company name, course code, date in filename and on page, wording that stands alone) matters more than PDF technology.
- **Challenged premise:** premise 4 contradicted premise 1: a dated document with a price attached to a PO reads as the price offer. Resolution chosen: keep 定價, label it 牌價, add the 以報價單為準 footer line (premise 4 revised above). - **Prototype notes adopted:** `.app-shell { height: 100vh }` + `.app-main { overflow: auto }` will clip print to one viewport-height page unless overridden; keep the sheet out of `course-detail.scss` to stay under the 4 kB budget; the QR must be an `<img src="data:...">`, never a CSS background, so it prints regardless of the "background graphics" setting; Chrome's default header/footer stamps the URL on the page.

### Print lifecycle

The sheet is correct whether the operator clicks the button or presses Ctrl+P, because the work happens on the browser's own print events, not in the click handler:

- `CourseDetail` declares `@HostListener('window:beforeprint')` and `@HostListener('window:afterprint')` methods (eng review 1A: the framework registers and removes the window listeners; no `addEventListener`, no `DestroyRef`).
- `beforeprint`: if `course()` is null, do nothing. Otherwise set `generatedOn` to now, save `document.title` into a private field, set it to the filename below, then call `ChangeDetectorRef.detectChanges()` synchronously. The call is required, not defensive: `app.config.ts:19` uses `provideZoneChangeDetection({ eventCoalescing: true })`, which defers post-event change detection to the next animation frame, so without it Chrome snapshots the page with the old date. `detectChanges()` re-checks only `CourseDetail` and its child sheet (1A), which is all that changed; it runs before the click's own change detection, so there is no recursive-CD error.
- `afterprint`: restore `document.title` only when a saved title exists, then clear the field (a Ctrl+P on 載入中 / 查無此課程 saved nothing and must restore nothing).

```
 operator                   browser                     CourseDetail                       DOM
   │  click 儲存為 PDF          │                            │                                │
   │──────────────────────────▶│  saveAsPdf(): window.print()│                                │
   │  (or Ctrl+P)              │───────────────────────────▶│                                │
   │                           │  beforeprint ─────────────▶│ course()? ── null ── no-op     │
   │                           │                            │   │ else                       │
   │                           │                            │   ├ generatedOn.set(now)        │
   │                           │                            │   ├ saved = document.title      │
   │                           │                            │   ├ document.title = 課程簡介_… │
   │                           │                            │   └ cdr.detectChanges() ───────▶│ sheet shows today
   │                           │  snapshot (print preview)  │                                │ @media print: shell hidden,
   │                           │◀───────────────────────────│                                │ cards hidden, sheet block
   │  Save as PDF / cancel     │                            │                                │
   │──────────────────────────▶│  afterprint ──────────────▶│ saved? ── restore title, clear │
   │                           │                            │        └ none ── no-op         │
```

The same diagram goes into `course-detail.ts` as a comment above the two host listeners (house rule: non-obvious flows carry an inline ASCII diagram, and keeping it current is part of any later change).
- `saveAsPdf()`: behind a `course()` guard, count the certifications `resolveCertifications()` could not resolve; if zero, `window.print()` directly. Otherwise (outside voice #2, eng review 12A) open a `p-confirmdialog` through `ConfirmationService`, the way `course-list.ts:163-175` does for delete: message `認證名稱未完整載入，PDF 將省略 {N} 筆對應認證。仍要繼續？`, accept → `window.print()`, reject → nothing. `CourseDetail` adds `ConfirmDialogModule` to `imports`, `ConfirmationService` to its `providers`, and `<p-confirmdialog />` to the template (it is a PrimeNG overlay: also hide it under `@media print` with the shell rules). Ctrl+P is not intercepted; the on-screen `認證 #n` chips remain the signal on that path.
- Filename: `課程簡介_{courseId}_{yyyyMMdd}`. `courseId` is `course.courseId.trim()` with every character in `\ / : * ? " < > |` replaced by `-` (`CourseId` is operator-entered `varchar(50)` with no format constraint); when it trims to empty, the filename uses `course.pkid` instead (the sheet body stays pkid-free). The date comes from `formatDate(now, 'yyyyMMdd', 'en-US')` in `@angular/common`; the sheet's on-page 產生日期 uses the `date` pipe with `'yyyy/MM/dd'`. Chrome and Edge propose `document.title` as the Save-as-PDF filename.
- Printing on 載入中 / 查無此課程: the detail page's print hide rule is keyed on a host class set only when a course is loaded (`host: { '[class.has-sheet]': 'course() !== null' }`, and `@media print { :host.has-sheet .page-header, :host.has-sheet .page-card { display: none } }`), so a Ctrl+P on an empty state prints the state message instead of a blank page.

## Success Criteria

- Operator on `/courses/{pkid}` clicks 儲存為 PDF (or presses Ctrl+P), the print dialog opens with the sheet only (no sidebar, top bar, cards, or audit badge), and `document.title` is `課程簡介_{sanitised courseId}_{yyyyMMdd}`, which Chrome and Edge propose as the Save-as-PDF filename.

- No excluded field (see premise 1) appears anywhere in the PDF, verified by the sheet unit test.
- Multi-paragraph 課程大綱 flows to page two without clipping and with a visible top margin on page two (15B verification); a course with every optional field null still renders every section with —.

### E-decisions (all auto-decided)

**E1 — The publish gate moves out of `ngOnInit` and into the click (fixes findings 1, 2, 8, 16).** `publishStatusPkid` only exists *after* the course response, so it cannot be an argument to the existing `forkJoin` (`course-detail.ts:68-79`) — A2 as written does not compile. And `PublishStatusSql.SelectBase` runs two `COUNT(*)` subqueries (Course, Promotion2) on every read, so wiring it into page load would pay two scans on every course view to serve a button most views never touch. Instead `saveAsPdf()` becomes async at click time: re-fetch the course (`getById`, which also fixes the stale-data window in finding 16 — the sheet then prints what is true at print time, not at page-load time) and fetch the publish status together, `catchError` on both, then raise **one** confirm dialog listing every reason that applies (unresolved certifications, not published, outside schedule), with precedence stated. **Fail-open**: if either fetch fails, print anyway with a note in the dialog; an unknown publish status must never block a sale. The operator is already waiting on a modal, so the extra round trip is free perceptually.

**E2 — `@page` cannot be scoped by a body class (fixes finding 3).** `@page` is a page-context at-rule with no descendant selector; `body.print-sheet @page` is not a thing, so A3/D13 as drafted would either leave the zero margin global (the leak they exist to fix) or never apply it (the internal CMS URL silently stamps a customer document). The mechanism that does exist is **named pages**: `@page sheet { size: A4; margin: 0 }` in `styles.scss`, plus `page: sheet` on the sheet's root element; unnamed pages keep `@page { size: A4; margin: 14mm 16mm }`. `page` shipped in Chrome/Edge 110, which the operators have.

**E3 — Print-margin spike before any layout work (fixes findings 3, 5, 6; supersedes D14).** Two claims underpin the whole margin design and neither is verified: that Chrome re-resolves the named page when the class/property appears during `beforeprint`, and that a repeated `<tfoot>` gives a per-page bottom margin (`thead` repetition is reliable; `tfoot` is markedly less so, and where it does repeat it sits immediately after content on the final fragment — which would put the "running footer" halfway up a one-page sheet, contradicting the Pass-1 layout). Table-as-layout also weakens `break-inside`/`orphans`/`widows` inside a tall cell and turns a prose document into a Table in the PDF tag tree, against D25/D30's own accessibility rationale. **Decision:** a 30-minute Chrome spike (**T0**, P1, blocks T1) tests named pages + `thead`/`tfoot` on a two-page sheet. Default structure until it says otherwise is **normal block flow, no layout table**. Ranked fallbacks, in order: (1) named page with zero margin + repeated `thead` for the top margin and a static footer on the last page; (2) `@page sheet { margin: 0 0 14mm }` — accept the bottom-edge stamp, keep top/left/right clean; (3) restore full margins and instruct the operator to untick "Headers and footers" (the pre-15B position). The plan states the fallback ladder so the implementer is never stuck.

**E4 — Success criterion corrected (finding 4).** Chrome honours `@page` margins only while the dialog's **Margins** dropdown is on *Default*; Minimum/Custom put the margin box back and the stamp with it. The criterion becomes "no stamp with default margins", and D10's help text carries the one line operators need.

**E5 — Body-class hygiene (finding 7).** The `print-sheet` class (or the `page` property, per E2) is set and cleared through one `DOCUMENT`-injected helper, cleared in `ngOnDestroy` as well as `afterprint`, so a tab-restore `afterprint` that never fires cannot leave every later page printing edge-to-edge — and a Karma spec that dispatches `beforeprint` without `afterprint` cannot pollute the next spec.

**E6 — Schedule comparison is string-based (finding 9).** `scheduleOn`/`scheduleOff` are `yyyy-MM-dd` `DateOnly` strings; `new Date('2026-09-09')` is UTC midnight, so any browser west of UTC would read a day early. Compare `formatDate(now, 'yyyy-MM-dd', 'en-US')` against the raw strings. `scheduleOff` is **inclusive** (the last valid day).

**E7 — Operator line is a label, not an attestation (finding 10).** `AuthService.userName()` reads `sessionStorage`, which the client can edit, and returns `''` when the profile is missing. The 承辦 line renders only when non-blank, the plan says in one sentence that it is a courtesy label with no server record behind it, and Open Question 3 must be signed off before a personal name goes onto documents that outlive the employee.

**E8 — Contact constants are gated (finding 11).** `COMPANY_NAME`, `COMPANY_PHONE`, `COMPANY_EMAIL` live in one exported object beside `PUBLIC_COURSE_URL`; the 業務洽詢 line renders only when the values are real. A placeholder phone number on a customer PDF is worse than no contact line.

**E9 — Where the print CSS lives (finding 12).** The 4 kB budget is a *warning* (8 kB is the error, `angular.json:50-53`) and production minifies component CSS, so D24's rules fit. The real constraint is that `@page` cannot live in a component stylesheet at all: page rules go in `styles.scss`, everything else in `course-sheet.scss`, and each file carries a comment pointing at the other.

**E10 — Dialog mask (finding 13).** Hide `.p-dialog-mask` alongside `p-confirmdialog` under print; settle the element question in code rather than in prose.

**E11 — Tests for the amendments (finding 14).** Added: the class/property is set on `beforeprint`, cleared on `afterprint` **and** on destroy; the gate fires for an unpublished status, for `today < scheduleOn`, for `today > scheduleOff`, and **not** on either boundary day; a failed publish-status or course re-fetch still prints (fail-open); the 承辦 line renders when the name is present and is absent when blank; one dialog carries multiple reasons; and `:host` is `display: none` on screen — without that last one, a regression silently dumps a second full course dump onto the detail page and nothing else would catch it.

**E12 — Same-vendor certification compares keys, not display names (finding 17).** `partnerName !== course.partner?.name` is a string compare against a nullable nav object, so a null `partner` would prefix every certification. Compare `CertificationLookup.partnerPkid` against `course.partnerPkid` — the key, never null.

**E13 — Two doc corrections (findings 18, 19).** The sanitiser example was wrong: `../../etc` yields `..-..-etc`, not `-` (the replace set has no `.`); harmless for a suggested filename, but the plan will not assert something untrue about its own code. And rather than constraining the sheet's markup forever, the two existing assertions at `course-detail.spec.ts:123,168` get scoped to `section.page-card a.detail-link`, which frees D20's footer link to be an ordinary `<a>`.

**E14 — `.app-main` padding pairing (finding 20).** Under the sheet's named page, `.app-main`'s print padding is explicitly `0`; otherwise page 1 stacks it with the sheet's own margins and page 2 does not, which is the exact bug the margin work exists to remove.

**E15 — Print is not covered by unit tests, and the plan says so (finding 15).** Karma cannot see print media: `thead` repetition, margins, the stamp, font selection and page-2 behaviour are covered by manual QA (T5) alone, on a feature whose entire output *is* the rendered page. | Aspect | Decision |
|---|---|
| Contract | `POST /api/courses/{id:int}/sheet` → `204 No Content`. No request body. `404` if the course does not exist (the controller reads it to log `CourseId`). Route constraint and parameter name match its sibling `Copy`, as every route on this controller does. |
| Auth | Nothing special: the global `FallbackPolicy` covers it by omission, exactly like every other endpoint. `TokenFreshness` applies unchanged. |
| Writes | **None.** No table is touched, so no `RowAudit` row and no `IRowAuditWriter` call — the house rule binds Insert/Update/Delete, and this is neither. `spec/conventions/backend.md` gets one line saying why this endpoint is the exception that proves it. |
